Inventario FabLab (con Matías)

Stack confirmado ya implementado
  • Frontend: React Native + Expo
  • Escaneo: Data Matrix (mejor que QR para piezas pequeñas)
  • Base de datos: MySQL
  • Backend: Spring
Modelo de datos
  • Cada ítem físico necesita identificador único propio (no un código compartido por tipo) — para rastrear daño/ubicación por unidad.
  • Distinguir consumibles (se descuentan por cantidad) de activos fijos (mantienen identidad individual) falta
Alcance funcional sugerido por Matías
  • No replicar todo Excel — solo: agregar, registrar daño, cambiar ubicación/sala, buscar por ítem y por sala.
  • Importar/exportar .xlsx para conectar con el inventario que otro grupo ya lleva en Excel falta
Pendientes bloqueante
  • Backend real (MySQL + Spring) — hoy todo vive en AsyncStorage local, sin servidor.
  • Falta preguntarle a Matías qué motor/hosting usar para desplegar el backend.

Organización del Drive (con Carmenza)

  • Archivo desordenado desde 2020; recién en 2023-1 empezó a tener algo de estructura.
  • Problemas de fondo: practicantes borran sus propios archivos al salir, fotos/carpetas sin nombre, criterios cambiantes cada semestre.
  • Acceso ya otorgado: carpetas de 2022 (la más desordenada) y 2026 (la más ordenada).
  • Plan: estructurar por año → semestre → tipo, usando 2022 como caso base y replicando con variaciones menores en los demás años.
